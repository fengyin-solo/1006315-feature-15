# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 结构沉降监测：观测成果整组处理

测绘队一次给几十个断面的观测成果，结构沉降监测支持**同一测次整组提交**，实现集中在：

- 领域模型：`frontend/src/data/settlement/`（`types.ts` 类型与口径常量、`legacy-seed.ts` 存量原始成果、`store.ts` 独立 localStorage 持久化与首次回填）。
- 业务规则：`frontend/src/api/settlement-service.ts`（校验、整组提交、超限联动、存量回填、对账、报表）。
- 页面：`frontend/src/views/settlement/index.vue`；预警回写在「设施检修管理」「运维值班交接」页各有一块联动清单。

规则与取舍依据（页面「规则说明」页签里也有同一份）：

1. **唯一键**：`监测断面＋监测日期(测次)`。同一断面同一测次在一笔里出现两次，只认先填的一条，另一条回执「批内重复舍弃」。
2. **先落者得（并发兜底）**：同一行被两笔同时提交，只认先落库的一笔，后到的在落库前命中唯一键，回执「重复挡回」。纯前端同步线程按到达顺序串行判定，等价后端唯一索引＋行锁。
3. **提交前阻断式检查**：监测编号重号（同编号对应不同断面/测次）、新测次累计沉降量缺失或非数值、日期非法、缺阈值为阻断项，检查不通过整批不落库；存量补录的累计沉降量缺失不阻断，转「待补清单」。
4. **同批事务 + 逐条回执**：入库、超限标记、检修回写、值班待办在一次提交内算完统一落盘，要么整批生效要么不生效；每条断面各自一条成功/失败回执，没交成的单列原因。
5. **超限联动**：切换日起新口径下累计沉降量 ≥ 预警阈值即挂「超限预警」，结论回写设施检修清单（待安排），并按同来源键在值班台账生成待办；安排/完工两侧同步。
6. **两条路径**：切换日常量 `CUTOVER_DATE = 2026-10-06`。上线先按「设备投运日期 → 监测日期」**幂等回填存量**（沿用测绘队原结论、不按新阈值溯及、不补生待办、缺失项进待补清单），再开放切换日起的新口径整组提交。两路径共用同一落库台账与唯一键，因此回填与新提交对同一断面测次不会产生两条结论。
7. **对账与一致读数**：每条新口径超限在未办结阶段对应恰好一条检修在办和一条值班待办，故对账口径为「检修在办数 ＝ 值班待办数」；累计超限数单独展示。概览卡片、台账、报表、对账全部从同一落库台账派生，不另存计数。

沉降域独立存储在 `urban-utility-tunnel:settlement:*` 几个键里；沉降页「回到刚上线状态」会清空这些键并重新触发一次存量回填。
